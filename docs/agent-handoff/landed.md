# What landed, where, and how to undo it

One row a unit, newest first. Read this first when something is wrong: find the unit by what a player or GM sees, then
its row says where the code is, which tests hold it, and the one command that takes it out.

How to use it:

- **Find the commit that broke something**: `git log --first-parent --oneline <commit of the last good row>..HEAD`, or
  `git bisect start HEAD <that commit>` with `bun test <the row's test file>` as the check.
- **See what a unit changed**: `git show --stat <commit>`; for a merge, `git diff <commit>^1 <commit> --stat`.
- **Undo a unit**: the command in its row. A merge is undone with `git revert -m 1 <commit>`; then run
  `bun run deps -- --write`, `bun run charts`, `bun run test`, and push as any change (the browser tests on the public
  repository first). A later unit that builds on it must be undone first: the "Needs" column says which.
- **Why a thing was built the way it was**: the notes file and section in its row. The trail (`decisions.tsv`) has the
  row of each push with what was checked.

A lead adds a row here in the same commit as the trail's row, every time a unit lands. A unit lands as one merge
commit (or one commit), never spread over several pushes, so one revert takes it out whole.
