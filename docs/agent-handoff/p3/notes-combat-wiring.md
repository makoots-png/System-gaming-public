# Notes: the combat view runs on the reducer (M3 unit C)

- Step 0 (reducer amendments): `CombatantId`, `HunterId` and `RemoteKey` are branded strings in `encounter-types.ts`; only `encounter-parse.ts` makes them (tests cast with small helpers). `Rules` and `Rank` come from `src/core/rules.ts`. `rankTier` reads the fixed `RANKS` list, so `parseCombatant` and `parseEncounter` no longer take the rules (an unknown rank is E). `Remote` has `tier` (0 to 5), `syncRemote` carries it and a status applied on a remote's turn takes it. New tests: a remote's tier as source, and a `@ts-expect-error` pair that fails the typecheck if a hunter id passes for a combatant id. `principle-type-system-discipline` decided where ids are made: the parser only.
- Reducer additions for the wiring (own commit): `summarize(enc)` (what End would report; `end` uses it, the End window reads it before the GM confirms) and `sourceOf(c, ctx)` (a combatant as a status source; the default source uses it, the view uses it for a monster ability's Apply chip). Changed: `syncRemote` no longer carries statuses. The GM counts a remote's status rounds down and tells the phone; the phone never ticks its own, so a sheet push every few seconds would have reset every countdown and nothing would expire. The old view did not copy statuses on sync either. The model test's random stream changed with it (the sync command draws less).
- Pin, before any app change (all seven files, one run): combat-turns 7 passed, character 10, table-session 4, gates-quests-dailies 11 passed 1 skipped 1 failed (the Lv 10 Job Change chain test timed out behind a System window; not a fight), customization 8, save 8, room-view 8. 56 passed, 1 failed, 1 skipped.
- Wiring commit: `save.ts` takes `Encounter` and `Combatant` from the reducer and its repair is `parseEncounter` (`newEncounter`, `newCombatant`, `fixCombatant`, `COMBATANT_KINDS` deleted). `combat.js` has one writer, `send(cmd)`: a single `store.update` runs `reduce`, stores the fight and writes the sheet effects (HP, MP, fatigue, statuses, a shadow's HP) straight onto the hunter in that same update, so there is no nested update; the hunter view's `settle` adds and drops Unconscious as before. After the update it sends room events, emits `combat:turn` and `combat:defeated`, toasts refusals and rolls each `rollTick` and sends the result. Gone: `mut`, `lg`, `at`, `resort`, `begin`, `emitTurn`, `turnEffects`, `mirrorConds`, `condsOf`, `normalizeIn`, `initMod`, `sortCmp`, `xpTotal`, `e.begun`, `e.turn`. 1024 lines to 900. Other views moved with it (`bestiary` builds and reads the new rows, `gates` reads hunters and remotes, and its fallback that wrote `gateId` by hand is deleted since `startFlow` always exists, `shadows` counts tries through `api.combat.setExtractTried`, `custom` reads `phase`). `combat-turns.e2e.ts`: 7 passed on the reducer.

- Choices and differences the lead should know:
  - Sheet effects are written onto the hunter inside the dispatcher's one `store.update` (no nested update), using `api.hunter.derived` for the maxima, as `damage`, `heal` and `applyOps` did. HP 0 still adds Unconscious through the hunter view's `settle`; the old tracker also logged "X falls Unconscious." in the fight, which is gone (the reducer logs the hit).
  - A `rollTick` for MP or fatigue on a monster or shadow is not sent (the old code ignored it too; the reducer would refuse it with a toast).
  - A status sent to a remote's phone carries a def for every status (`s.def` or the rules' def): the phone drops a status without one.
  - End: the window reads `summarize(e)` and shows `Math.max(1, rounds)`, so a fight that never started still says "1 round" as before (the reducer's summary says 0). `combat:end` now carries `{ encounter, summary }`, the reducer's ended fight and summary.
  - Mid-fight initiative for added combatants now logs "Initiative: Goblin C 10." (the reducer's line); the old code logged nothing. A setInitiative line reads "X: initiative N." (was "X initiative set to N.").
  - `grep -n "begun\|\.turn\b\|mirrorConds\|\.defeated =" src/views/combat.js` finds one line, the CSS selector `.cmb-card.turn`, which the browser tests use and the brief says not to restyle.
  - The Share initiative checkbox with no fight still only changes the checkbox, as before (a new fight always starts with shared initiative on).
  - `principle-minimize-reader-load` decided `kindTag`: the reducer's `remote` kind is shown and published as `hunter` in one helper, so the card, the row, `targets()` and the room document agree.
