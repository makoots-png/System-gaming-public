Evidence for bug 2, Nov 11 21:35Z: the room-onboarding port saw 'opening an invite link joins' take 52 s once and about 9 s on the other runs. Same shape as the sync stall: a join or change that sits for tens of seconds and then arrives.

Evidence for bug 2, Nov 11 21:42Z: the room-view port saw 'paste, upper-case, Enter to join' take 54 s once on a first run, 8 s after. Two separate helpers saw a join take 52 to 54 s once. That is close to a fixed delay (a backoff or a 45 s timeout plus the normal 8 s), not random load. M6 should look for a timer of that size on the join or first poll path.

Evidence for bug 2, Nov 11 22:00Z to 23:10Z: table-session draft run 2, after the player's first sheet PUT at 5.1 s neither phone logged an /api response until 99.6 s. My own first run of table-session failed the same way and the second passed. The customization port widened its room waits to 45 s and room-view and room-sync-fixes to 30 to 40 s for the same reason. An Opus helper is root-causing it now (p3/stall-investigation.md). Once fixed, bring those waits back to the 15 s default.

Found by the reducer's model test in M3, before the reducer was wired in (both fixed, each kept as a named test in `tests/encounter-model.test.ts`):

- Prev could land on a combatant that an initiative re-roll had moved ahead of the current turn. Its turn had not started this round, so the fight held a current turn that was not marked as started, and Next from there skipped it. Prev now goes back only to turns that started.
- Revive on a monster or shadow at 0 HP left it up at 0 HP. It is now refused with "Heal it to bring it back".


Found while building the room protocol (M5):

- A replayed award paid twice. The cursor stops a replay within one room link, but a reload of an old page, a rejoin or a GM resending after a timeout that did land all brought an event back. A new browser test rewound the phone's cursor, reloaded, and read 50 gold where 25 was due. Now `settings.sync.applied` keeps the ids of the last 200 hunter-changing events, and an award, quest, HP or status event applies at most once per phone. The test is in `tests/e2e/room-sync-fixes.e2e.ts`, and the ring is checked in `tests/applied.test.ts`.
- A player could post a roll or a quest update in another player's name. The server did not compare the sheet key in `by` with the device that sent the request. It now answers 403 "not your sheet", including for a device id that is only a prefix of the key's device. Tests in `tests/server-rooms.test.ts`.

Found by the room system model test in M8 (fixed, kept as two named tests in `tests/room-system-model.test.ts`):

- A removed player was sometimes never told. The GM taps Remove on Kai. Before the server's answer reaches the GM's phone, the GM reloads the app, or opens a new room. The server has already deleted Kai's sheet, but Kai's phone stays in the room: the "removed" notice reached a player only through a doc the GM's phone wrote in a second request, after the first one answered, and that second request never went out. Kai's sheet then came back on its next change once the server's 20 s block ended. A lost doc write did the same, and Allow back had the same two-step gap. Now the server writes the removal record in the same request that deletes the sheet, lifts it in the Allow back request, and refuses a hand-written `_kicked` doc.

Found by the screenshot comparison, fixed in the sweep (M8 unit 7):

- The Hobgoblin's "Martial Advantage: +2d6 once per round" drew a "+2" attack button and the text "d6"; the 2d6 was never rolled. The ability reader took a leading `+2` as a to-hit bonus without checking that a digit or `d` followed. Now a leading bonus must end at a word boundary, so `+2d6` is dice. `tests/ability.test.ts`; the exception in `tests/monsters.test.ts` is gone.
- The fight log said a monster marked defeated "is down." while its card said DEFEATED (and 0 HP logged "is defeated."). The reducer now logs "is defeated." for both, and the nobody-is-up refusal says "Everyone is defeated." `tests/encounter.test.ts`.
- The Status window opened scrolled down when its first focus was the Name field below the fold (a pointer that is not a touch screen, the screenshot run's landscape shot): the opening `focus()` scrolled the field into view and the focusin handler then centred it 250 ms later, so the title, Rounds and the first chips were out of view. The opening focus now does not scroll, and the centring listener is added after it. `tests/e2e/combat-turns.e2e.ts` (three phone sizes, and a short window with a mouse, which failed before).
- The GM's Table feed came back after a reload (it is kept for the session) but forgot which rolls had been applied, so the Apply button returned and the same roll could be applied twice. The applied mark was a Set beside the stored feed. It is now a field of the feed row, stored with it. `tests/e2e/table-session.e2e.ts`.
- A hunter whose job the GM changed from Necromancer to another job could still extract shadows, and a job the GM added to the rules' extract jobs did not let its hunters extract: `canExtract` was a stored flag set when an extract job was given and never cleared. The flag is gone; `canExtract(R, job)` in `src/core/rules.ts` answers it from the job. `tests/rules.test.ts`.
- A Create or Join tap still running when the campaign was replaced (import, restore, reset) said "Could not reach the server", and undoing the hunter the join had made set the new campaign's active hunter to the old campaign's. The link now answers a running tap with the `replaced` notice; the tap's promise is refused with kind `replaced`, the Room view shows no error for it, and nothing is undone in the new campaign. `tests/link.test.ts`.
- A second tab of the same browser stayed in a room after the first tab left it (or joined another): `storage` events replaced the save but not the link, and the stale link could write its room back. sync.ts now raises `replaced` when another tab's save names another room or GM key than the link's. `tests/e2e/room-view.e2e.ts`.

Open, noticed in M7 and not fixed:

- A player in a room cannot be given a Job Change chain: the room `quest` offer carries no chain, so the GM can only start a chain for a hunter on the GM's own phone. It predates phase 3. The customization phase covers it.
