# Notes: the combat reducer (M3 unit B)

- Step 1: types in `src/core/combat/encounter-types.ts`, boundary parser in `encounter-parse.ts`, both re-exported from `encounter.ts`. `parseEncounter` re-sorts a running list into turn order, falls back to the first up combatant when `currentId` is unknown, reads a running fight with no combatants as setup, and forces a monster or shadow at 0 HP down. Tests: `tests/encounter.test.ts`.
- Step 2: `reduce` with add, rollInitiative, setInitiative, setShareInit, next, prev (plus setState and applyStatus, which the turn tests use), and `initiativeNeeds`. A monster added mid-fight to a pack that already rolled copies the pack's init and tie in `add`, so `initiativeNeeds(enc, ctx, [newId])` is empty for it. Next landing on a turn that already started (a combatant re-sorted behind the current one) only logs "Back to X.", as the old code did. Rolling initiative with nobody up is refused (the old code started on a down combatant).
- Step 3: changeHp, changeMp, changeFatigue, removeStatus, plus tests for setState, statuses and turn starts. Decision: a monster or shadow changes state on HP only when HP crosses 0 (to 0: down and `defeated`; from 0: up). A monster the GM put down by hand at HP above 0 stays down when healed, and a later hit to 0 does not report `defeated` again. The old code brought any healed monster back. A remote hunter has no tier in the model, so a status applied on its turn has source tier 0. A monster's or shadow's source id is its combatant id; a hunter's is its hunter id; a remote's is its remote key.
- Step 4: remove, linkGate, note, setExtractTried, syncRemote, end, clear. Removing the current combatant when nobody left is up rests the turn on whoever now holds its place (or the first), marks it reached without starting it, and keeps the round. `ended.encounter` is the input encounter itself (the reducer never mutates, so no copy is needed). `syncRemote` updates every row with that remote key and logs nothing; a key not in the fight is a no-op, not a refusal.
- Step 5: `tests/encounter-model.test.ts`, a seeded (mulberry32) model test: 2,500 sequences of 1 to 40 commands over two local hunters (the test carries out their sheet effects), a remote, a shadow, a wolf pack and an ogre; deep-frozen input, every invariant of the brief checked after every command, about 4 s. It found two bugs, both fixed and kept as named tests with explicit commands:
  1. Prev could land on a combatant that a re-roll or `setInitiative` had moved ahead of the current turn. Its turn had not started this round, so the fight held a current turn not marked as started (and Next from there would skip it again). Fix: Prev goes back only to turns that started; it skips the others.
  2. `setState up` on a monster or shadow at 0 HP left it up at 0 HP. Fix: refused, with "Heal it to bring it back".
  Coverage check (counted once in a scratch script): about 5,500 Nexts, 2,300 Prevs, 2,100 removes and 9,400 turn starts while running.
- Step 6, mutation check (each made by hand, `bun test` run, then restored; `git diff` empty afterwards):
  1. Next ignores `reached` (every landing starts a turn): 7 tests fail, including the model test.
  2. `remove` does not bank a down monster's XP: "a removed defeated monster keeps its XP" fails.
  3. `defeated` reported on every hit that leaves a monster at 0, not only on going down: 2 tests fail.
- Open for the lead: rolling initiative refreshes a local hunter's stored `initMod` from its sheet (the sort uses the stored one). `rollTick` is emitted for every per-turn op, not only HP, MP and fatigue (the edge chooses what to roll). Nothing is wired into the app yet.
