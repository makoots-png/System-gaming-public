Crash-resistance rules (user-approved, Nov 11): the API stream to Anthropic keeps dropping mid-reply on long responses (35 cut-offs so far, each costing ~15 minutes before the retry), and long helper tasks like "prove and fix all sync findings" lost hours to it. So: (1) Scope helper tasks small, one bug, one module or one feature per helper, never "all findings" or a whole subsystem in one task. (2) Helpers write findings, plans and patches to files under docs/agent-handoff (or commit) in small increments as they go, and return only a short summary (a few hundred words max) plus file paths, never long reports or full diffs in a reply. (3) Keep your own replies short too, and checkpoint progress to files (lead-report.md or a notes file) after each unit so a cut-off or restart loses minutes, not hours. (4) Time-box each helper task, and if one runs past about an hour, stop it, record where it got to, and split the rest. (6) When you split or retry a helper task, give a fresh helper the original brief, every later directive, and the previous helper's report and branch, rather than resuming the old one (poteto-mode "fresh subagents by default"). (7) Keep a decision trail with the show-me-your-work skill, so a restart picks up from the log instead of from memory. A guard (docs/agent-handoff/guard.py, run every 15 minutes) enforces part of these rules automatically: it flags helpers open past an hour, helper replies over ~800 words, resumed helpers, more than an hour without a checkpoint, and cut-off bursts.
