## Steps

1. **Types and tables first.** `fight-types.ts`: `Fight = Setup | Running` with `now: Tick`, `currentId`, the grid, the log; the row is unit 3's `Body` (extend it there if a field is missing, do not wrap it); the `Command` union and the `Effect` union of design 3.3 (new members listed there; a refusal is an effect with a reason from one closed union, shared with `resolve`'s). Each command and each effect gets one line saying what it is. A fight has sides (`party` and `foe`), so who is a foe is data and never a view's guess. `bun run typecheck`. Commit.
2. **The machines as tables.** The fight's own states (no fight, setup, running, ended) and the channel's (design 4.1: none, holding, fired, broken) are each a `TABLE` the typecheck checks cell by cell, as `src/core/gates/gate.ts` does it; read that file and copy its shape. Stagger, shield and threat are data with a rule each, not machines; say so in a one-line header. Commit.
3. **`reduce(fight, command, ctx)`** returning `{ fight, effects }`, never throwing, never mutating, refusing with a `refused` effect. One `case` per command with an exhaustive `never` check. `start` (openings from the d20s the command carries, default places from `space.ts` for anyone without one), `act` (calls `resolve`, then applies the channel, stagger, threat and shield consequences and the `vitals` effect for a local hunter), `move` (design 4.6: the path, its cost on the timeline, a root refuses), `endTurn`, `release`, `setIntent`, `place`, `settle`, `add` and `remove` mid-fight (joining at `opening`), `end`, and `undo` only if the design defines exactly what it restores (if not, leave it out and say so). One function begins a turn (`startTurn`): it advances `now` to the next `at`, settles that body's per-round ops pro rata, grows its channel, decays its threat table by elapsed time, drops expired statuses and shields for everyone by time, and emits `turnStarted`. A held (stunned) or down body is passed by rule, not by a flag a view reads. The fight ends when a side has nobody up, with a `Summary` (time in rounds, who is down). Commit when `tests/fight.test.ts` covers each command.
4. **`tests/fight.test.ts`**: one or more tests per command, expected values from the design (the timeline tables for who acts when, section 4's tables for channel charge and firing at half charge when broken, stagger costing 1.5 rounds and regrowing, larger-holds shields, threat decay by time, a taunt forcing the target and ending early on a Discipline build, movement cost). A refused command leaves the fight deeply equal. Commit.
5. **`tests/fight-model.test.ts` and `tests/models/fight2-play.ts`**: the seeded random player, as `fight-play.ts` is for the old fight: a mixed fight of two sides (three hunters of different builds, a shadow, three monsters and an elite or a boss), random legal and illegal commands with the dice numbers generated from the seed, 2,500 fights, and after every command these invariants: ids unique; HP, mana and fatigue within their bounds; nobody shares a tile; every place is on the grid and not a wall; `now` never goes back; the current body is the lowest `at` among those up and not held; no per-round op settles twice for the same span (total settled time per status equals elapsed time while it was on); a channel's charge is within 0 and its max; a down monster never acts; `parseFight(JSON.parse(JSON.stringify(fight)))` gives the same fight; the input fight is never mutated; a fight with one side down is ended. Two replays for any bug the model finds, named by what a player would have seen. Commit.
6. **`fight-parse.ts`**: `parseFight(raw)`, the one reader of a stored or received fight (boundary-discipline): bounded lengths, every enum through its list, a place on the grid, a formula parsed once. The model test's round trip uses it. Commit.

## Rules

- Pure core TypeScript, strict, no `any`, no dependency, no module-level `let`, no `Math.random`: every die comes in on the command.
- No balance number as a literal: all from `RULES.fight` through `ctx.rules`.
- The reducer is the only writer of a body's place, HP, shield, stagger, channel, threat and statuses. Rule modules return new values; nothing else assigns them. (A lint test for it comes with the wiring unit; write the code so that test will be one grep.)
- A test's expected value comes from the design or the paper tables, never from a run of the code under test.
- Keep `fight.ts` readable: `reduce` is a switch of short calls. If it passes about 450 lines, split by domain (for example `fight-turn.ts` for `startTurn`), not by phase.
- Plain whole sentences in notes; comments only for a why.
